# Local project data audit (v1.9.8, 12 Nov 2026)

Asked for in the owner's 12 Nov directive (section 4, "Local Project Database Audit"): project list, settings and `.swb`
backup / restore must survive upgrades without corruption or data loss. Read: `BackupFactory`, `BackupRestoreManager`,
the precompiled `lC` (project list, `javap -c`), `MyProjectSettingActivity`, `NewProjectActivity`, `ModernProjectDefaults`,
and what an app update touches (`SketchApplication.onCreate`, the v1.9.8 `BuiltInCache`).

## Where the data is

| What | Where | Written by |
|---|---|---|
| Project list entry (name, package, version, colours, `sc_id`) | `/.sketchware/mysc/list/<sc_id>/project`, AES/CBC (key = iv = `sketchwaresecure`) | `lC` (precompiled) |
| Blocks, views, files, libraries, resources, settings | `/.sketchware/data/<sc_id>/…` (logic, view, file encrypted) | `eC`, `hC`, `iC`, `kC`, `ProjectSettings`, `BuildSettings` |
| The open project's working copy | `/.sketchware/bak/<sc_id>/` | the editors |
| Images, icons, fonts, sounds | `/.sketchware/resources/{images,icons,fonts,sounds}/<sc_id>/` | the managers |
| Generated project / build output | `/.sketchware/mysc/<sc_id>/` (deleted at every build and export) | `yq`, `Dp` |
| Backups | `/.sketchware/backups/<project>/<name>.swb` (or the folder set in Settings) | `BackupFactory` |
| App caches (built-in libraries, compiled resources, build cache) | the app's own `cacheDir` | `Dp`, `BuiltInCache`, `ResourceCompiler`, `RClassCache` |

An app update touches none of the project folders: they are on shared storage, keyed by `sc_id`, and no code migrates
them at start. Old projects keep their stored settings (`ModernProjectDefaults` never raises them). The v1.9.8 version
check at start (`BuiltInCache.onAppStart`) moves only the app's own unpacked built-in libraries and compiled library
resources aside.

## Findings and what was done

| # | Finding | Effect | v1.9.8 |
|---|---|---|---|
| 1 | Restore took `lC.b()` (highest *readable* project id + 1). A project whose list file is missing or damaged (a restore cut off half way, a folder deleted by hand) keeps its `data/`, `resources/` folders under an id `lC.b()` hands out again. | The backup was copied *into* those leftovers: a merged, corrupt project. | `ProjectIds.free`: the next id with no folder in `mysc/list`, `data`, `bak`, `mysc` or `resources/*`. Used by restore (`BackupRestoreManager`) and by cloud restore |
| 2 | Creating a project (`NewProjectActivity`, `MyProjectSettingActivity`) has the same id source, and creation empties the id's data folder. | Creating a project could delete the data of a project whose list file was damaged (recoverable until then). | Both use `ProjectIds.free(lC.b())` |
| 3 | `BackupFactory.unzip` wrote every entry where its name pointed, `../` included. | A hand-made or downloaded `.swb` could write outside the backup folder (other projects, libraries). | Entries outside the target folder stop the restore ("couldn't unzip the backup") |
| 4 | `BackupFactory.getNewScId` sorted ids as text ("999" after "1000") and crashed on a folder name that isn't a number. | Unused by the app today; would hand out an existing id past 999. | Numeric maximum + 1, through `ProjectIds` |
| 5 | A backup that failed while zipping left the half-written `.swb` and the temp folder. | The next backup of the project got a `_d` name; a broken `.swb` sat next to good ones. | Both deleted on failure |
| 6 | `getProject` / `writeEncrypted` (restore's project file) never closed their `RandomAccessFile`. | File handles leaked per restore. | try-with-resources |

Not changed (recorded): the precompiled writers (`lC`, `eC`, `hC`, `iC`, `kC`) write in place, not through a temp file and
rename; a write cut off by a crash can still damage one project file. Changing them means replacing jar classes with
source (their own release). `FileUtil.writeFile` (the fork's and upstream's source writers) is atomic since v1.8.x.

## Checked how

ART harness (API 31, APK classes), `githubtest 940` (v1.9.8 `h.GitHubTest`): fixture 940 backed up with `BackupFactory`;
a leftover `data/<lC.b()>` folder planted; `ProjectIds.free` skipped it; the `.swb` restored as a new project under the
free id with the same name, the planted folder untouched; `getNewScId` numeric and free; a `.swb` holding `../evil-outside.txt`
refused with nothing written outside. On a phone: not run (device checks list).
