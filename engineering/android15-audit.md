# Android 15 (API 35) compatibility audit

Audited: commit `c82aba4` (v1.8.1) and the APK built from it (`app-minApi26-debug.apk`, sha256 `2db64781…bc79b`, versionCode 171, min 26, target 34). Date: 2026-10-04.

## Summary

- **Nothing in this audit was run on a phone or an emulator.** Every "OK" below means "source and off-device experiments show no conflict with the documented Android 15 rules". It is not a device result.
- **IDE on Android 15 (target 34): no BROKEN item found.** Storage, AAPT2 execution, install, receivers, PendingIntents and notifications follow the documented rules for target 34. Edge-to-edge is not enforced for the IDE because it targets 34.
- **16 KB pages:** the bundled 64-bit AAPT2 binaries (`arm64-v8a`, `x86_64`) have LOAD alignment `0x4000` (16 KB). The 32-bit ones (`armeabi-v7a`, `x86`) have `0x1000` (4 KB). Not run on a 16 KB device.
- **Dynamic code loading:** one path only: Kotlin compiler plugins (`kt_plugins/*.jar` on shared storage) through `PathClassLoader`. RISK for Kotlin projects that use plugin jars. No `DexClassLoader` / `InMemoryDexClassLoader` anywhere in the APK.
- **BROKEN, apps built with the IDE:** an APK made with **Export** (sign with test key or own keystore) is signed with scheme **v1 only**. Android 11+ refuses v1-only APKs that target API 30+. New projects target 37. The **Run** build is not affected (v2 + v3, plus v1 when minSdk < 24).
- **RISK, apps built with the IDE at target 33+:** storage permission code still asks for `READ/WRITE_EXTERNAL_STORAGE`; no `POST_NOTIFICATIONS` is generated for FCM / OneSignal; the debug crash screen relies on a background activity start.

### LOAD alignment per ABI (A3)

`readelf -lW app/src/main/jniLibs/<abi>/libaapt2.so`, LOAD lines, last column:

| ABI | File type | LOAD alignment | ≥ 0x4000 | Meaning on a 16 KB device |
|---|---|---|---|---|
| arm64-v8a | ELF64 static EXEC, 4,603,392 bytes | `0x4000` (all 3 segments) | yes | Meets the documented 16 KB requirement. This is the binary a 64-bit ARM phone uses. |
| x86_64 | ELF64 static EXEC, 4,865,064 bytes | `0x4000` (all 3 segments) | yes | Meets it. Used by x86_64 emulators and by the tests on this machine. |
| armeabi-v7a | ELF32 static EXEC, 2,242,744 bytes | `0x1000` (4 segments) | **no** | 4 KB aligned. The 16 KB page names only `arm64-v8a` and `x86_64`; whether a 16 KB device ever runs this binary is UNKNOWN. |
| x86 | ELF32 static EXEC, 3,953,296 bytes | `0x1000` (4 segments) | **no** | Same as armeabi-v7a. |

The 64-bit binaries were built with `-Wl,-z,max-page-size=16384` (`tools/aapt2-static/SOURCES.md`). The 32-bit ones are the upstream files from 2022.

## Not made Android-15-only

- minSdk floor: **26** for the shipped flavor `minApi26`; a `minApi21` flavor exists and compiles (`app/build.gradle:39-52`). Nothing in this audit proposes raising it.
- The IDE's own code has **no** `SDK_INT >= 34` or `>= 35` branch (grep over `app/src/main/java`, `app/src/minApi26`, `kotlinc/src`). The only "35" check is inside the text generated for user apps (`SystemBarsCode.java:57`).
