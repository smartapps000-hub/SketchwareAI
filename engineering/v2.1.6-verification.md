## 4. Post-update logout audit

What the four screenshots show: the card "GitHub didn't accept this phone's sign-in" with its token print equal to the
one made at the sign-in: GitHub answered 401 (asked twice, 3 s apart) for the very token the app saved; the app didn't
change, lose or replace it. Paths that end or change a sign-in in the app, read again for v2.1.6:

- `TokenStore.clear()` is called only by `GitHubSession.signOut`, which is called by the Sign out buttons and by
  `SingleDeviceGuard` (another phone's later sign-in mark; that shows "signed in on another phone", not the 401 card).
- An update keeps the token: same package and key, `TokenStore` binds it to ANDROID_ID | signing certificate | user id,
  none of which an update changes; `SessionLog` records installs / updates, and no update path signs out (v2.1.2).
- The 401 card comes only from `GitHubSession.markRefused` (an exact 401 from GET /user, asked twice).
So GitHub ended the token on its side. GitHub's documented causes ("Token expiration and revocation"): the user revoking
it (or the app's authorization), the limit of 10 tokens per user, OAuth app and permission set (an eleventh sign-in ends
the oldest unused one), a token unused for a year, or the token pushed to a public repository or gist. The security log of the signed-in account shows which
(`oauth_authorization.destroy` with its actor and time); the owner's screenshot was another account's log, hence the
account note. What v2.1.6 changes for the user: the sign-in window opens by itself, and waiting backups continue after it.

## 6. Not run / limits

- Nothing on a phone: the sign-in window, Settings, the Demo tab and the security-log note are drawn with layoutlib or
  read; the automatic window, the permission question and the update from the Release link need the phone.
- The demo's network part (api.github.com) can't be reached from here; its JSON code ran on a hand-made answer in
  GitHub's documented shape.
- `SignatureGuard` reads nothing in the harness (no PackageManager): its rule and the token refusal were run with a set
  verdict.
- The release key is the repository's public test key: a changed copy re-signed with it passes the check. Real
  protection needs a private release key kept off GitHub (the owner's decision; phones would need one reinstall or a key
  rotation). A copy patched to skip the check also passes.
- The GitHub Release must be created by the owner (proxy refusal); until then updates come from the binaries branch.
