Labels: ART = the IDE APK's own classes ran on an Android 12 (API 31) ART runtime in the build sandbox
(`tools/art-harness`, no Android framework, no device). HOST AAPT2 = the x86_64 `libaapt2.so` the APK ships, started by
the IDE's own `ResourceCompiler` from ART. DEVICE = the owner's phone. **Nothing in this file was run on a device.**

## 2. Two engine fixes the harness found

1. **Min SDK below 21: the app's own classes were not in classes.dex.** Upstream merges MultiDex, then every library,
   then the project's DEX last. Once the libraries pass 64K methods (v1.8.3 AppCompat projects do), the project's
   classes landed in classes3.dex; Android 4.x loads only classes.dex before `MultiDex.install()`, so `SketchApplication`
   would not be found at start. `Dp.getDexFilesReady` now merges the project's DEX right after MultiDex when min SDK < 21.
   Min SDK 21+ (every new project) is unchanged.
2. **DEX merge overflow.** With that order, `DexMerger` threw `BufferOverflowException` in `transformDebugInfoItem`:
   it reserved 2x the debug info, but a 1-byte string/type index becomes 3 bytes once the merged DEX has 16384+ strings.
   It now reserves 3x (+8); unused space is compacted afterwards, as before.
