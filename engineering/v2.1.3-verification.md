## 4. Reviews

Three separate review passes of the diff (an agent; code reading, nothing run).

First pass (the whole v2.1.3 diff): no HIGH; 2 MEDIUM, 9 LOW, all fixed:
- MEDIUM: 2 MB parts four at a time could pass GitHub's write limits for large backups → the part size grows with the
  backup (about 48 parts at most, 16 MB at most).
- MEDIUM: an icon picked in New Project was lost when Android stopped the app while the picker was open (the id was read
  after the result) → the id is kept in the saved state, an icon picked before the id is saved when it arrives, the project
  is marked with an own icon only when the file was written.
- LOW: the id and its folders now in one step under the restores' lock; a project named "NewProject…" made the list read
  fail (name fallback); the tile's letters after the id; Follow's state overwritten by a stale read; the Review button
  promising a read that failed; local file errors retried as "Connection lost"; failure texts cut at 5 lines; a resumed
  draft keeping an earlier version's .swb; the old notice id range also holding the update's notice; `removeAsset` reading
  only the first 100 files (now by every page).

Second pass (those fixes): no HIGH or MEDIUM; 5 LOW and 2 nits, all fixed: old-file removal after publishing best effort
(a refused removal no longer fails a stored backup); the expanded notice at 7 lines (large fonts); the tile reset when an
icon can't be saved; New Project says when it waits for a restore; a short packed file isn't a network error; a bounded
cause walk.

Third pass (those fixes): no HIGH or MEDIUM; 2 LOW, fixed: a resumed draft's stray files are removed after publishing and
trimming old versions is best effort (a write limit there can't fail a stored backup); "couldn't be read" isn't replaced by
"reading". Kept as a limit: the GitHub sample and the project settings dialog pick project ids without the restores' lock
(as before).

## 6. Decisions left to the owner

- Demos stay on the phone; backing one up and making it public stays a per-demo choice (nothing goes public by itself).
- Follow needs the `user:follow` permission on GitHub's sign-in page; existing sign-ins keep working and are asked to sign
  in again only when Follow is tapped.
- Sketchware AI's own GitHub Discussions are still off (Settings › Features › Discussions on GitHub).
- Git LFS: with v2.1.3 the `binaries` branch holds 32 LFS files, about 4.6 GB of the free 10 GiB storage. Bandwidth is
  10 GiB a month on GitHub Free: about 70 downloads of the 143 MB APK; the required update makes every phone on v2.1.2
  download it once. Older APKs on `binaries` can be removed by the owner to free storage.
