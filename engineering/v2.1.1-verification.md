## 4. Reviews

Three separate review passes of the diff (agents; code reading, nothing run).

First pass (v2.1.0 → the first full v2.1.1 build): 3 HIGH, 1 MEDIUM, 8 LOW, all fixed except one left to the owner:
- HIGH: a second publish deleted every store screenshot (staged pictures deleted after a publish, then
  `removeExtraShots(…, 0)`) → staged pictures stay; a publish without pictures keeps the store's.
- HIGH: jobs resumed after a sign-in ran under whichever account signed in (a publish could make another account's
  repository public) → `Job.login`, resume / retry / run refuse another account, Sign out forgets waiting jobs.
- HIGH: `RejectedExecutionException` crash when leaving a creator page while it loaded → guarded, on the main thread.
- MEDIUM: Restore's shared-link lookup waited behind icon downloads → own worker, quick requests, none after a network
  error.
- LOW: a deleted stats post never recreated; a search replaced the saved store list; icon caches never refreshed; a
  confirmed publish could be dropped when the screen closed; the sheet's Sign in again could do nothing; main-thread
  disk work; pictures staged during a publish deleted → all fixed. The 👀 view is a public reaction under the viewer's
  account: left as the owner asked for counted views, with a caption on the app page saying so.

Second pass (the fixes and the round icon): no HIGH; 2 MEDIUM, 8 LOW, all fixed:
- MEDIUM: the sheet said "It ran again" for a job dropped for another account or after a sign-out → says why; such jobs
  stay for their own account's Retry.
- MEDIUM: a week-old icon refreshed without a usable sign-in got a private repository's 404 and was deleted → kept.
- LOW: "@null" texts; the publish took the account at queue time, not the screen's (now `Store.login`, also checked in
  `runStore`); the account rule for Play Store / Publish jobs only and in every retry path; checked before the test
  runner (the suite covers it); stale pictures shown first and refreshed behind, only a decodable picture replaces one;
  publish texts; clearing the search restores the store; an existing stats post is reused (no duplicate).

Third pass (the Play Store app page in correction 5's order): no HIGH; 1 MEDIUM, 4 LOW, all fixed:
- MEDIUM: the publish line ("Re-published • Update #N · ★ · date") shared a one-line row with the version pill and was
  cut on a 360 dp screen → its own row, up to two lines, a shorter date.
- LOW: capsules 40 dp → 48 dp (touch target); TalkBack names now start with the visible label ("Install APK: …"); an
  unused `pill(int)` removed; the class comment described the old page order. A render at 360 dp and font scale 1.3

## 6. Decisions left to the owner

- Sketchware AI's own GitHub Discussions are still off: Community shows other repositories until Settings › Features ›
  Discussions is switched on for smartapps000-hub/SketchwareAI (an outward change: not made from here).
- The automatic 👀 view is a public reaction under the viewer's GitHub account (said on the app page); it can be made a
  tap instead.
- Git LFS: with v2.1.1 the `binaries` branch holds 30 LFS files, about 4.3 GB of the free 10 GiB storage. Bandwidth is

  v2.1.0 download it once. More phones than that in a month need a paid data pack (or older APKs removed only frees
  storage, not bandwidth).
