# v1.8.5: what was changed and how each part was checked

Labels as in v1.8.4: ART = the IDE APK's own classes on an Android 12 (API 31) ART runtime in the build sandbox
(`tools/art-harness`, no Android framework, no device). LAYOUTLIB = Android 14's view/resource/text code on the JVM
(Paparazzi 1.3.5, `tools/layoutlib-renders`), not a device. HOST = Linux tools in the sandbox. DEVICE = the owner's phone.
**Nothing in this file was run on a device.** APK signing (ReleaseSigner, ApkSigner) was not changed; AAB signing was
(section 4), with the owner's go after v1.8.4.

## 6. Review before release

A separate review of the first v1.8.5 build (code that can't run here and the generator rules) reported 2 high, 3 medium
and 4 low findings; all were checked against the code and fixed in the final APK (commit "review fixes"):

1. `DesignTheme.load` filled the editor's shared project cache (`jC`, preferring the backup): after "No" in the restore
   dialog the editor could mix backup and saved data. Now reads with its own `iC`/`hC` instances.
2. The Material inflater turned every `<Button>` into a MaterialButton, which tints a background of its own (property
   colour, image, `setBackground` from code) with the primary colour. Theme back to the AppCompat inflater + SketchButton.
3. MaterialSwitch broke code that types `Switch` (compile error or ClassCastException) and tinted thumb/track drawables:
   `scanCode`.
4. DayNight with user-chosen dark colours, icons and `setTextColor` blocks: unreadable at night. Light theme; DayNight is a
   roadmap item (opt-in).
5. ItemEditText reset image backgrounds on attach (also in non-Material 3 projects). Changes the background only when it
   enters or leaves the outlined look.
6. `setHint(R.string.x)` on an outlined field didn't compile: `SketchTextField.hint(TextView, int)`.
7. An injected `visibility` or code that moves/re-lays out the field: not wrapped.
8. Only L8 fell back; D8 with the configuration didn't; L8 temp folders leaked; a damaged extraction was never redone:
   all fixed (section 2).
9. ItemRadioButton kept its Material tint after a convert: undoes only its own tint, like ItemCheckBox.

Found by the review as correct: desugared DEX packaging (debug, merged, AAB), `bin` cleaning, atomic cache writes, APK
signing unchanged, AAB keystore handling and stream closing, bundletool 1.18.3 API, the manifest `package` attribute
stripped only in the Android Studio export, `enter`/`exit` pairing and line counts, legacy generated output identical apart
from the rewarded-ad import, ItemButton/ItemSwitch/ItemCheckBox fields and behaviour in non-Material 3 projects.
Not verified by the review: exported local `.aar` files without `R.txt` under AGP 8.12. The Gradle build of the export
(section 4a) then showed it was a real defect, plus the export's missing FCM / Google sign-in dependencies. The cut hint of
an outlined `wrap_content` field was found by the layoutlib render (section 5). Both fixed in the final APK.
