## 4. Changed from the ask, or not built, and why

- **"Instant auto-close" of the browser tab**: `finishActivity(7311)` closes a Custom Tab that runs in the app's task
  (Chrome's). A browser that opens the page as its own task stays open there; the app still closes its window, signs in
  and shows the projects list. Android 15 cuts a background app's network, so when GitHub's answer can only be read
  after the user comes back, the close follows the return (the check runs at once then).
- **Google / Apple** stay in the browser: Google refuses its sign-in inside an embedded WebView, and the user agent is
  not changed to hide the WebView (v2.0.1 decision). The tap now starts the browser sign-in at once instead of a blank page.
- **Share link of a private repository**: the backups live in the private `SketchwareAI-Projects` repository, so the link
  opens only for the account that made it (and its collaborators). Making the repository public, or a public copy of a
  backup, would publish the project's code: not done without the owner's word.
- **Repository scanner** lists `.swb` backups. A plain Sketchware project folder in a repository (data files, not a .swb)
  isn't recognised as a project.
- **Event names**: the directive's `onUserLoaded` … `onError` are the helper's `Listener` methods; the blocks' events are
  named `onGitHubUserLoaded` … `onGitHubError` so they can't clash with other components' events. A sixth event
  (workflow started) answers the run-workflow block.
- **"getFileContent" / "triggerWorkflow"** are the blocks *get file* and *run workflow*; a *has token* block was added.
- **Build Doctor "diagnostics"** for the component are advice for compile errors and the token warning; GitHub's answers
  at run time (bad token, permission, rate limit, not found, workflow trigger) are explained in the app's *error* event.
  No automatic changes to a user's token or code.
- **Known limit**: a user's own custom component named "GitHub" or with id 2026 is shadowed by the built-in one.
- **TLS 1.2 on Android 4.4**: GitHub accepts TLS 1.2 or newer only. Apps with min SDK 19 reach GitHub on Android 5.0+;
  on 4.4 the error event says TLS 1.2 must be switched on (the helper doesn't install a security provider).

## 5. Device checks (the owner)

1. Install v2.0.2 over v2.0.1. Sign out if signed in. Drawer: "Sign in with GitHub" must be whole.
2. Tap it and sign in with your GitHub password on GitHub's page: after GitHub's home feed appears, the window must go to
   the code page by itself; tap Authorize; the window and the drawer close and the drawer card shows you (long lines
   scroll).
3. Sign out, sign in again and tap **Continue with Google**: the browser must open GitHub's device page at once (code
   copied, no blank page). Paste, approve, come back (or wait): signed in.
4. A project's **Back up → Back up to GitHub**: the sheet must count to 100%; then the share button next to its #number;
   tap it: link copied, share sheet.
5. **Restore projects → GitHub import project → ⓘ**: the three steps; paste a repository link: its backups listed; Import
   one: the sheet counts to 100%.
6. A new project: Components → + → GitHub, then the GitHub blocks (drawer category "GitHub") in onCreate, e.g. *get user*
   with an empty name and a Toast in *user loaded* / *error*; Run on the phone (without a token GitHub allows 60 calls an
   hour per network).
7. Projects #644, #623, #606: Run each once.

If something fails: a screenshot (the sign-in window's status line says what happened), or the compile log (Copy).
