Found while building it (fixed before the release; `known-errors.json`):
- An event without blocks is written as nothing; whether its blank line stays depends on the event, so the marked
  generation differed at empty events (902/903 refused). The map now matches such an event against the normal text.
- Myers' diff can put a pure insertion next to an equal `}` outside the event: `LineDiff.slide` moves such runs into
  the event.
- A field holding `//` in a string (a URL) was refused as a comment: comments are now found outside string and
  character literals only (`JavaMembers.hasComment`); fixture 919 checks both cases.

## 4a. Export to Android Studio and local libraries (found by this release's suite)

The first suite run exported fixture 920 and the project had no Retrofit: the export never wrote the project's local
libraries (upstream gap; earlier fixtures had none). Fixed in f6b8e9f (`GradleExport.writeLocalLibraries`,
`architecture-state.md`). A second problem showed in the first fixed build (db8d4e1): the generated code imports
`<package name>.*` for a local library, and the installer had given plain jars their Maven group as package name
(`com.squareup.retrofit2`), which only the on-phone build's empty R class makes exist; Gradle failed on it. Plain jars
now get no package name; the export empties such an import when the package holds no class and no resources.

## 5. Review before release

A separate agent reviewed the v1.8.8 diff (`git diff b2bdd42..HEAD`; javap of eC, gC, Fx, jr, br): 1 high, 4 medium, 2
low-medium, 8 low. All fixed before the final build:
1. (high) a field written over several lines was stored with a line break, which the project file can't hold (variables
   after it lost on the next load). Declarations are joined on one line; comments or annotations in them are refused.
2. (medium) lines outside every member were dropped and the save reported success: refused with their line.
3. (medium) the Code tab read the project data on the UI thread while the design editor was still loading it: waits for
   the load.
4. (medium) on Android 7.1 and older (minApi21) D8 can't run: Dx is used there (Java 7 class files).
5. (medium) folder listing, sizes, delete and enable ran on the UI thread: background, search debounced.
6. (low-medium) "With the libraries it needs" was read only when Find ran: changing it resets the plan.
7. (low-medium) the Add dialog's Find had no catch (a POM without groupId threw): caught and shown.
8. (low) only RuntimeException restored the data: any Throwable restores the snapshot; a failed reload after a
   successful save says so.
9. (low) importing a file named `..jar` could replace `local_libs`: names are made unique, leading dots stripped.
10. (low) + New class could create a file named like an activity (which then replaces the generated activity):
    refused.
11. (low) the editor stayed editable while saving: locked.
12. (low) edited line ranges were computed from offsets (spurious refusals); a variable's type change was a remove +
    add refused while blocks used it: exact ranges from the diff; a type change keeps the variable.
13. (low) Maven `*:*` exclusions ignored: honoured.
14. (low) `LineDiff` kept a full array per step: only the diagonals each step can read (O(D²)); one hunk above D 1500.
15. (low) enabling could switch off a same-named library of another or unknown group, and an unreadable library list
    was overwritten as empty: only when both groups are known and equal; an unreadable list is left alone.

The review covered the diff up to e43efc6. The URL-field fix (section 1) and the export of local libraries (section 4a)
came later; both were run on ART (fixture 919, exports of 920 built with Gradle), and the export Activity's change is
one call, the same the harness makes.
