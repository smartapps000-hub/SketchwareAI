## 2. Material 3 in generated apps

A project with AppCompat on is a Material 3 project since v1.9.5. Its theme is `Theme.Material3.DayNight.NoActionBar`
(`Theme.Material3.Light.NoActionBar` for projects made before the dark setting existed), with the colour roles written
by `M3Palette` (Material Color Utilities, from the project's primary colour) into `values/` and `values-night/`. Dynamic
colour (`DynamicColors.applyToActivityIfAvailable`) is a switch and is off by default, by the owner's decisions of
24 Oct and 2 Nov: with it on, the project's own colours give way to the wallpaper's.

| Palette widget / block | What the generator writes | Class |
|---|---|---|
| Button | `<package>.SketchButton` (a MaterialButton); with an injected `Widget.Material3.Button.*` style the same class in that variant | **Material 3** |
| EditText | outlined `TextInputLayout` + `<package>.SketchTextField` (a TextInputEditText) | **Material 3** |
| Switch, CheckBox, RadioButton | MaterialSwitch, MaterialCheckBox, MaterialRadioButton | **Material 3** |
| ProgressBar | LinearProgressIndicator / CircularProgressIndicator | **Material 3** |
| CardView, Toolbar | MaterialCardView, MaterialToolbar | **Material 3** |
| FAB, BottomNavigationView, TabLayout, AppBarLayout, CollapsingToolbarLayout, TextInputLayout, drawer | `com.google.android.material.*`, styled by the theme's Material 3 defaults | **Material 3** |
| Snackbar block | Material `Snackbar` | **Material 3** |
| Web blocks' dialogs (SketchWeb) | `MaterialAlertDialogBuilder` with AppCompat | **Material 3** |
| SeekBar, Spinner, AutoCompleteTextView, RatingBar, TextView, ImageView | AppCompat widgets through the inflater, tinted with the theme colours | AppCompat (legacy look) |
| Dialog component | `android.app.AlertDialog.Builder` (the generated file imports `android.app.*`) | **framework dialog**, not Material 3 |
| DatePickerDialog, TimePickerDialog components | `android.app.DatePickerDialog` / `TimePickerDialog` | **framework dialogs**, not Material 3 |
| ProgressDialog component | `android.app.ProgressDialog` (a deprecated class) | framework |
| ListView, GridView, SearchView, CalendarView, DatePicker and TimePicker in a layout, WebView, VideoView | framework views | no Material class with the same API |
| Bottom sheet | no block exists; `BottomSheetDialog` from the bundled Material library is Material 3 in add-source code | not offered as a block |
| Navigation bar | BottomNavigationView (the Material 3 navigation bar under this theme) | Material 3 |

Measured on fixture 908's layout as the final APK wrote it: `SketchButton`, three `TextInputLayout`, `MaterialSwitch`,
`MaterialCheckBox`, `MaterialRadioButton`, `CircularProgressIndicator`, `MaterialCardView`, `MaterialToolbar`; plain
`SeekBar` and `Spinner`; `styles.xml` parent `Theme.Material3.DayNight.NoActionBar`.

A widget stays the plain class when the project's code touches it in a way the Material class would break (`scanCode`:
`Switch`-typed code, drawables or tints set from code, layout params moved), when the user replaced `styles.xml`, an
activity's Java file or a layout, or when the project has AppCompat off (then nothing is Material 3: the theme is the
framework's `Theme.Material.Light`).

Not Material 3 and not a small fix: the three framework dialogs. `MaterialDatePicker` and `MaterialTimePicker` are
fragments with different listeners (the `onDateSet` / `onTimeSet` events and the `DatePickerDialog` type would change),
and theming the framework dialogs to the Material 3 shape needs light and night dialog themes that have to be rendered
before they ship (section 6). "Identical to an Android Studio template" holds for the theme and for the first nine
rows; it does not hold for the rows marked AppCompat or framework.

## 4. What was patched

### 4.1 Contrast (IDE), as decided by the owner on 11 Nov

The first version of this pass made the label on the orange buttons near-black. The owner rejected that the same day:
the IDE keeps pure white labels and its dark + orange glass look, and the orange is deepened instead. Final state:

- **Call-to-action surfaces only** (`ob_cta`, `ob_cta_pressed` in `drawable/` and `drawable-v24/`, `ob_safe_cta`,
  `ob_safe_cta_pressed`): #E8501C → #F97316 becomes **#D34115 → #C64F14**. White on it is 4.63:1 at the weakest point
  of the gradient (was 3.75:1 down to 2.80:1). Pressed: #C83D13 → #BC4A12 (5.07:1); the glass version keeps its brighter
  rim and stronger glow. Labels, the play icon, every layout and every other orange (tiles, FAB, toolbar, selected
  pills, `ob_orange`, `ob_amber`) are as in v1.9.7.
- **Block guide**: labels stay white. `BlockShapeView.readable(color)` deepens a block colour (same hue and

  file brown #A1887F (3.31:1) is drawn #857169 (4.60:1), web blue #4A6CD4 (4.79:1) is unchanged. The step badges use

- **Hint grey** in `ObsidianAdapter` (non-EditText hints of classic dialogs on the dark sheet): #71717A → #8E8E93
  (4.07:1 → 6.03:1). No orange involved.

- **Selected segment pills** (owner's go, 12 Nov): property panel Basic / Recent / Event and the New Project engine row
  used `ob_tile_orange` when selected (white 3.48:1 down to about 2.9:1). `ob_seg_pill`'s selected state is now its own
  `ob_seg_pill_on` (glass in `drawable-v24`, plain gradient below), #D34115 → #C64F14, white 4.6:1. `ob_tile_orange`
  (main-screen tiles, dialog icon tiles) is unchanged.

Not covered: the palette tabs of the logic editor (`selector_palette_tab_round`, #F4511E → #FF9A4D). They carry icons,
not text, apart from the AdMob settings tabs; left as they are.

### 4.2 Storage permissions in generated manifests (`Ix.legacyStorageMaxSdk`)

READ_EXTERNAL_STORAGE and WRITE_EXTERNAL_STORAGE written for File blocks and components now carry
`android:maxSdkVersion="32"` when the project targets API 33 or higher. On Android 13+ such an app is not granted
them (the request comes back "denied" without a dialog: documented for READ, reported consistently for WRITE), and the
generated code runs `initializeLogic()` on any answer, so the app behaves as before on every Android version; the
declaration simply no longer applies to Android 13+ devices. Projects with a lower target keep the plain declaration.
This is the manifest half only: it gives File blocks no access to shared storage on new Android versions, and Android
Studio's `ScopedStorage` lint warning on the WRITE line stays (measured).

### 4.3 Network security configuration (`Ix`, `yq`)

Android 17's notes announce the end of `usesCleartextTraffic` in a later release and name the replacement: a network
security configuration, plus the attribute for min SDK below 24. Wherever the generator writes
`usesCleartextTraffic="true"` it now also writes `android:networkSecurityConfig="@xml/sketch_network_security_config"`
and `res/xml/sketch_network_security_config.xml` (`<base-config cleartextTrafficPermitted="true" />`): the same
permission as today in the form that keeps working. Not written when the manifest editor already sets
`networkSecurityConfig`, when it sets `usesCleartextTraffic` to false, or when the build setting that removes the
attribute is on. `Ix.settleNetworkSecurityConfig` runs on the manifest after the XML command blocks: if one of them
also set the attribute, the generated attribute and file are dropped (two would stop aapt2). In Android Studio the
file draws one lint warning, "Insecure Base Configuration": true, and equally true of the attribute it stands beside.

### 4.4 Lint errors in exported projects

Android Studio's lint (AGP 9.5.0) on the exported fixture 908 reported 14 errors. Ten came from generated code and are
fixed at the source:

| Lint id | Count | Cause | Fix |
|---|---|---|---|
| MissingClass | 1 | the manifest named `.DebugActivity`; an export has no such class | declared for Run builds, or when the project has its own `DebugActivity.java` |
| NewApi | 6 | `SketchWeb.Client` overrides that pass the call on to the wrapped client | `@TargetApi(27)` on the class: the system calls each override only from the API level that added it |
| UnspecifiedRegisterReceiverFlag | 1 | `SketchWeb.register`: the branch for Android 12 and older has no flag | `@SuppressLint`: the flag is passed on Android 13+ |
| RestrictedApi | 1 | `SketchButton` calls `setSupportBackgroundTintList` | `@SuppressLint("RestrictedApi")` |
| WrongConstant | 1 | `SketchwareUtil.hideKeyboard` passed `HIDE_IMPLICIT_ONLY` as the show flag | `SHOW_IMPLICIT`: the same value (1), so the compiled code is identical |

All are annotation-only or value-identical: generated apps run the same code as before. The camera feature tag (4.5)
removed an eleventh. Left (section 6): `SuspiciousIndentation` in every activity's `_getCheckedItemPositionsToArray`
helper, and two that come from the fixture's own layout (`WebViewLayout`, `Orientation`).

### 4.5 Camera feature tag (`Ix.settleCameraFeature`, owner's go 12 Nov)

Wherever the final manifest text (after the XML command blocks, on both manifest paths in `yq`) declares
`android.permission.CAMERA`, with either quote style, and has no feature tag for `android.hardware.camera`,
`<uses-feature android:name="android.hardware.camera" android:required="false" />` goes in front of `<application`,
with the same indent and line ending. A camera feature tag the project already has (manifest editor, command block) is
left alone: a second, different one would stop Gradle's manifest merger. Effect: Google Play no longer hides apps with a
Camera component or the camera permission from devices without a camera. Installing and running on a phone with a
camera is unchanged. Trade-off (review): on a device without any camera app, upstream's take-picture block starts
`ACTION_IMAGE_CAPTURE` without a check; there the app would now be installable and that block would fail.

## 6. Found, not patched (not small, or the owner's call)

1. **Framework dialogs** (Dialog, DatePickerDialog, TimePickerDialog components) are not Material 3. Plan: generated
   dialog themes in light and night for the look (renders first), then optional Material picker components with their
   own events.
2. **Shared storage**: Photo picker block (no permission) and "save to Downloads / Pictures" through MediaStore, as
   agreed on 2-3 Nov; File blocks stay for app folders.
3. **`ACCESS_LOCAL_NETWORK`** for projects targeting 37 that talk to LAN devices: an entry in the permission picker
   and group table.
4. **Large screens at target 37**: a note in the build log when a project targeting 37 fixes its orientation.
5. **Take-picture block without a camera app** (upstream's block, see 4.5): a check before
   `startActivityForResult`, now that such devices can install the app.
6. **`SuspiciousIndentation`** in the generated `_getCheckedItemPositionsToArray` helper of every activity: needs a
   change to the activity template (braces or one more line), which every source-map and Java-editor fixture reads.
7. **Palette tabs** of the logic editor: icons on #F4511E → #FF9A4D (4.1).
8. **v4 signature for exported APKs**: only useful for `adb install --incremental`; needs a second output file and
   the owner's go, because APK signing is to stay untouched.
9. **AppCompat widgets without a drop-in Material class** (SeekBar → Slider, Spinner → exposed dropdown): new palette
   widgets, as in `v1.9.5-xml-m3-audit.md` X5.
10. **R8 9.x, AGP 9.5.1, Material 1.14**: each its own migration.
11. **Min SDK below 21 exports** leave out `android:name=".SketchApplication"` unless the project has its own class;
    whether MultiDex is then installed on Android 4.x in an exported build was not traced (seen while reading `Ix`).
