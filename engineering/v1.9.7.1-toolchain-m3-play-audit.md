audit" and "generated apps audit & immediate M3 / Play Store parity audit" (the second is a subset of the first), with

**How to read this.** "On-device toolchain" means the tools inside the IDE that build the user's projects on the phone.
The IDE's own Gradle build is named separately. Version numbers of outside tools were read on 11 Nov 2026 from Google
Maven's `maven-metadata.xml` and from the installed SDK packages. Nothing here was run on a phone.

## 2. Material 3 in generated apps

A project with AppCompat on is a Material 3 project since v1.9.5. Its theme is `Theme.Material3.DayNight.NoActionBar`
(`Theme.Material3.Light.NoActionBar` for projects made before the dark setting existed), with the colour roles written
by `M3Palette` (Material Color Utilities, from the project's primary colour) into `values/` and `values-night/`. Dynamic
colour (`DynamicColors.applyToActivityIfAvailable`) is a switch and is off by default, by the owner's decision of 24 Oct
and 2 Nov: with it on, the project's own colours are replaced by the wallpaper's.

| Palette widget / block | What the generator writes | Class |
|---|---|---|
| Button | `<package>.SketchButton` (a MaterialButton); with an injected `Widget.Material3.Button.*` style the same class in that variant | **Material 3** |
| EditText | outlined `TextInputLayout` + `<package>.SketchTextField` (a TextInputEditText) | **Material 3** |
| Switch, CheckBox, RadioButton | MaterialSwitch, MaterialCheckBox, MaterialRadioButton | **Material 3** |
| ProgressBar | LinearProgressIndicator / CircularProgressIndicator | **Material 3** |
| CardView, Toolbar | MaterialCardView, MaterialToolbar | **Material 3** |
| FAB, BottomNavigationView, TabLayout, AppBarLayout, CollapsingToolbarLayout, TextInputLayout, NavigationView (drawer) | `com.google.android.material.*`, styled by the theme's Material 3 defaults | **Material 3** |
| Snackbar block | Material `Snackbar` | **Material 3** |
| Web blocks' dialogs (SketchWeb) | `MaterialAlertDialogBuilder` with AppCompat | **Material 3** |
| SeekBar, Spinner, AutoCompleteTextView, RatingBar, TextView, ImageView | AppCompat widgets through the inflater, tinted with the theme colours | AppCompat (legacy look) |
| Dialog component | `android.app.AlertDialog.Builder` (the generated file imports `android.app.*`) | **framework dialog**, not Material 3 |
| DatePickerDialog, TimePickerDialog components | `android.app.DatePickerDialog` / `TimePickerDialog` | **framework dialogs**, not Material 3 |
| ProgressDialog | `android.app.ProgressDialog` (deprecated class) | framework |
| ListView, GridView, SearchView, CalendarView, DatePicker, TimePicker (in a layout), WebView, VideoView | framework views | no Material class with the same API |
| Bottom sheet | no block exists; `BottomSheetDialog` from the bundled Material library is Material 3 when used in add-source code | not offered as a block |
| Navigation bar | BottomNavigationView (the Material 3 navigation bar under this theme) | Material 3 |

A widget stays the plain class when the project's code touches it in a way the Material class would break (`scanCode`:
`Switch`-typed code, drawables or tints set from code, layout params moved), when the user replaced `styles.xml`, an
activity's Java file or a layout, or when the project has AppCompat off (then nothing is Material 3: the theme is the
framework's `Theme.Material.Light`).

Not Material 3 and not a small fix: the three framework dialogs. `MaterialDatePicker` and `MaterialTimePicker` are
fragments with different listeners (the existing `onDateSet` / `onTimeSet` events and the `DatePickerDialog` type would
change), and theming the framework dialogs to the Material 3 shape needs light and night dialog themes that have to be
rendered before they ship. Planned as its own item (section 6). "Identical to an Android Studio template" is true for
the theme and the widgets in the first nine rows; it is not true for the rows marked AppCompat or framework.

## 4. What was patched (commit db84753)

### 4.1 Contrast (IDE)

- Label and icon on the orange call-to-action surfaces (`ob_cta*`, `ob_safe_cta*`): white → `ob_on_cta` #0B0B0D.
  White was 2.80:1 to 3.75:1; the new label is 5.24:1 to 7.02:1. The approved gradient is unchanged. Pressed state of
  the legacy buttons: start colour #CF4416 → #DC4C18 so the dark label keeps 4.77:1 there.
- Hints #71717A → #8E8E93 in `library_downloader_dialog.xml` and `logic_popup_add_component_temp.xml` (4.07:1 → 5.21:1
  on the field, 6.03:1 on the background).
- Block guide: `BlockShapeView.onColor(color)` returns white where white reaches 4.5:1, otherwise #0B0B0D; used for the
  block's label and the step badge. Permission teal 3.67:1 → 5.35:1, file brown 3.31:1 → 5.94:1; web blue keeps white
  (4.79:1). The block colours are the editor's, unchanged.

The other choice for the buttons (keep white, darken the orange to #B93C0A / #C2410C) changes the approved gradient,
so the label was changed instead. To go back: `ob_on_cta` in `colors_ob.xml` is the one value for layouts; the three
Java call sites carry the same literal.

### 4.2 Storage permissions in generated manifests (`Ix.legacyStorageMaxSdk`)

READ_EXTERNAL_STORAGE and WRITE_EXTERNAL_STORAGE written for File blocks and components now carry
`android:maxSdkVersion="32"` when the project targets API 33 or higher. On Android 13+ such an app is never granted
either of them (the request is answered "denied" without a dialog), so the app behaves as before on every Android
version; the declaration no longer appears for Android 13+ devices, and Android Studio's lint no longer flags it in an
exported project. Projects with a lower target keep the plain declaration. This is the manifest half only: it does
not give File blocks access to shared storage on new Android versions.

### 4.3 Network security configuration (`Ix`, `yq`)

Android 17's notes announce the end of `usesCleartextTraffic` in a later release and name the replacement: a network
security configuration, plus the attribute for min SDK below 24. Wherever the generator writes
`usesCleartextTraffic="true"` it now also writes `android:networkSecurityConfig="@xml/sketch_network_security_config"`
and the file `res/xml/sketch_network_security_config.xml` (`<base-config cleartextTrafficPermitted="true" />`): the
same permission as today, in the form that keeps working. Not written when the manifest editor already sets
`networkSecurityConfig`, when it sets `usesCleartextTraffic="false"`, or when the build setting that removes the
attribute is on.

## 6. Found, not patched (not small)

1. **Framework dialogs** (Dialog, DatePickerDialog, TimePickerDialog components) are not Material 3. Plan: generated
   `android:alertDialogTheme` / date and time dialog themes in light and night for the look (renders first), then
   optional Material picker components with their own events.
2. **Shared storage**: Photo picker block (no permission) and "save to Downloads / Pictures" through MediaStore, as
   agreed on 2-3 Nov; File blocks stay for app folders.
3. **`ACCESS_LOCAL_NETWORK`** for projects targeting 37 that talk to LAN devices: a "Local network" entry in the
   permission picker and group table.
4. **Large-screen behaviour at target 37**: a note in the build log when a project targeting 37 fixes its orientation.
5. **v4 signature**: only useful for `adb install --incremental`; would need a second output file next to the APK and
   the owner's go, because APK signing is to stay untouched.
6. **AppCompat widgets without a drop-in Material class** (SeekBar → Slider, Spinner → exposed dropdown): new palette
   widgets, as in `v1.9.5-xml-m3-audit.md` X5.
7. **R8 9.x / AGP 9.5.1 / Material 1.14**: each its own migration (keep-rule consumer; patch bump with a full suite;
   min SDK 23 + API 35 resources).

Sources for the outside facts: Android developers "Behavior changes: apps targeting Android 17" and "Behavior changes:
all apps" (Android 17), "Target API level requirements for Google Play apps"; Google Maven metadata for bundletool, r8,
gradle, material, constraintlayout, desugar_jdk_libs.
