## 4. Not run, known limits, decisions

- **Not run here**: the phone screens (sign-in window, drawer card, project-card pills, progress sheets, System
  Settings, the blocks guide), DesignActivity's save paths calling `projectSaved`, WebView and GitHub's pages, the
  Android Keystore itself, GitHub with the owner's account (the fake GitHub follows GitHub's documented answers; only the
  raw blob read ran against the real API), a large project uploaded over a mobile network, a generated app's GitHub calls.
- The HTTP 401 the phone got near the end of a large upload has no confirmed cause (nothing found in GitHub's
  documentation or reports). v2.0.3 sends 4 MiB parts, tries a refused part again while GET /user accepts the sign-in
  and shows GitHub's message and request id: the next failure, if any, names the part and the id to report.
- Known limits: a public copy is forgotten (and stays public) when the project is backed up under another GitHub account
  on the same phone; a copy moved to an organisation counts as gone (the card says Private while it may be public there);
  a record from before the second review pass (no repository number) is made private by its recorded name; v2.0.2 can't
  import a backup in parts; if WebView reports a failed load before the page start, the window can still say "Type the
  code" over the error page (the fill script does nothing off github.com).
- Decisions taken (owner can change them): the share link of a public project is its repository's page; a private
  backup's link names the .swb while the backup is one file (v2.0.2 imports it) and the parts list when it is in parts;
  Private acts at once, Public asks first; the sample project is made once per install only when no project of that
  name exists.
