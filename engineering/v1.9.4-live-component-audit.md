Compared against Sketchware Pro 6.4.0-rc05 as it is in this repository: commit `216c013` is the upstream source zip
unchanged (`git diff 216c013 HEAD` = everything this fork changed). Counts are from the source files; the precompiled

## 1. What 6.4.0-rc05 has that the fork lacks

Nothing was removed. Palette definitions are upstream's: `BlocksHandler.java` (256 block definitions, unchanged),
`mod/hasrat/blocks/ExtraBlocks.java` (43, unchanged), `ExtraPaletteBlock.java` (2 lines changed: the WebView / VideoView
palette condition), events `a/a/a/oq.java` (162 event cases, unchanged), 34 component types (`ComponentBean`). The
palette draws 586 distinct block rows across the 10 categories; all of 6.4.0-rc05's rows are present. What the fork
changed is the code the blocks and views generate (`Jx` +114/−11, `Lx` +99/−51, `Ox` +77/−4, `yq` +161/−17 lines) and
the toolchain around it.

## 3. Storage permissions (File blocks)

Generated today: `READ_EXTERNAL_STORAGE` (+ `requestLegacyExternalStorage` for target 28+) and `WRITE_EXTERNAL_STORAGE`
without `maxSdkVersion`, requested at run time by the permission code (`PermissionManager`). On Android 13+ these
permissions are never granted, so FileUtil on shared folders works only in app-specific folders there. Remediation in
the roadmap (item 2).

## 4. Build and signing (unchanged by this audit)

Run builds: zip-aligned (`-P 16`) and signed v1 + v2 + v3; APK export v1 + v2 + v3; AAB SHA-256 JAR signature and 16 KB
page alignment (bundletool); every ELF in the IDE 16 KB LOAD-aligned. A project's own 4 KB `.so` gets a warning (it can
only be rebuilt by its author).
