# v1.8.4: what was changed and how each part was checked

Labels: ART = the IDE APK's own classes ran on an Android 12 (API 31) ART runtime in the build sandbox
(`tools/art-harness`, no Android framework, no device). LAYOUTLIB = Android 14's view/resource/text code on the JVM
(Paparazzi 1.3.5, `tools/layoutlib-renders`), not a device. HOST = Linux tools in the sandbox. DEVICE = the owner's phone.
**Nothing in this file was run on a device.** The signing code (ReleaseSigner, ApkSigner, ZipSigner/CustomKeySigner) was
not changed, as asked.

"compileSdk 34" in this release means the platform **user projects** are compiled and linked against (the bundled
android.jar the on-device AAPT2/ECJ/D8 use). The IDE's own Gradle build stays AGP 7.3.1 / compileSdk 30 / target 34; moving
the IDE itself to compileSdk 34 needs AGP 8 + JDK 17 and is its own release.

## 4. Telugu typography

Android shapes text with Minikin + HarfBuzz using the font's own GSUB/GPOS whenever the Typeface is a real OpenType font;
there is nothing to "bind". What breaks Telugu in apps is **metrics**: a font whose ascent/descent are smaller than the
ink of stacked clusters overlaps the next line and is cut at the view's edge. `SketchFonts.apply` (the font block, rewritten on
the same line) measures the font's own shaped ink and gives the view only the room that is missing.

|---|---|---|
| Android's shaping vs HarfBuzz: 8 Telugu strings (the owner's test strings + deep conjuncts) × 4 fonts (2 TTF, 2 OTF/CFF) loaded with `Typeface.createFromAsset`, `TextRunShaper` glyph ids and positions vs uharfbuzz 0.56.3 | LAYOUTLIB + HOST | 32 of 32 identical (glyph ids; positions within 2/1000 em) |

A separate review of the code that can't run here (designer, dialogs, generated helper, ELF/DEX/class-file parsers,
AAB packaging) found four defects in the first v1.8.4 build, all fixed before this APK (commit "review fixes"):
