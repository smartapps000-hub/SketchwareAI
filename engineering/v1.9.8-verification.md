## 4. Not built, and why

- **Native C++ / Java integrity check (package + signing certificate, "prevent tampered clones")**: the APK is signed
  with the public AOSP test key (`testkey.keystore`, in this repository), so a clone signed with it carries the same
  certificate digest and passes; the source is public (GPL-3.0 for the fork's code), so any check is one rebuild away.
  It protects nothing until a private release key exists. Declined before (v1.9.7) and listed as out of scope in
  CLAUDE.md.
- **Remote switch that locks the IDE (`app_enabled=false`), workspace locked until sign-in, 45-day build expiry**: an
  offline IDE that stops opening when a file changes or after 45 days without network breaks the offline-first rule
  for every user; and with "Enable Device Flow" still off on the OAuth app (the owner's screenshot), a required sign-in
  would lock everyone out of v1.9.8 at once. The same file drives notices instead; making sign-in required is the
  owner's decision after sign-in works on his phone.
- **Google One-Tap (Credential Manager) and e-mail code sign-in**: needs a Google Cloud OAuth client (Web client ID) for
  `com.sketchware.ai` registered with a private release key's SHA-1 (the public test key must never be registered),
  current AndroidX in the IDE (the precompiled classes use a 2021 bundle), and for e-mail codes a server that sends mail
  (no secret can live in the APK). `auth-telemetry-review.md`.
- **Community store on GitHub Discussions (GraphQL) + Releases**: a store needs a repository with Discussions and
  categories set up, a token for every GraphQL read, moderation, and its own screen; one release doesn't attempt
  everything. Roadmap.
- **Remote override of the Client ID** (owner's "if ever needed"): not built; whoever can change the file could send
  sign-ins to another OAuth app.
