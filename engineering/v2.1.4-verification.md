## 4. Reviews

Three separate review passes (an agent; code reading, nothing run).

First pass (the whole diff): no HIGH; 4 MEDIUM, 11 LOW, all fixed or recorded:
- MEDIUM: the notification listener could stay unbound right when the code page loaded (an unbind in flight, a disarm on
  the page between loads) → the window disarms only after a real read, an unbind clears the connection, a disconnect while
  armed asks for a new binding.
- MEDIUM: stale or wrong codes could be submitted (a code from the password step on the Confirm access page, a waiting
  code in a two-factor field, the same rejected code again, a pull request number) → codes count only from when the page
  offered one, never twice per window, a waiting code only on e-mail / code pages, keyword-only parsing.
- MEDIUM: the clipboard was read (Android's "pasted" notice) at every focus return → the clip's description first, only
  text copied while the window was away is read.
- MEDIUM: Android 15 hides one-time codes from notification listeners that aren't trusted system apps → the switch is
  offered on Android 8-14 only; on 15+ the copy-and-return path is the one the bar describes.
- LOW: focus return no longer overwrites the status line; Open Gmail right after E-mail me a code counts; a window whose
  screen went away stops (and the sign-in goes on); notification extras that can't be read are skipped; recovery and
  passkey pages vetoed; the probe reads text without layout and only while in front; follow counts guarded and read again
  on return; the highlight taken only by the list; the store's copy merged and saved under the publish's lock; a project
  made private is no longer kept first; "Why?" only for refusals; `isNotificationListenerAccessGranted` on API 27+.
  Kept as a limit: the app page's "@creator ✔ / ★" counts the creator's apps from the phone's copy of the store and this
  app's downloads; the creator page counts from GitHub's search and every app's downloads, so the two can differ.

Second pass (those fixes): no HIGH; 1 MEDIUM, 4 LOW, all fixed: Gmail's and the browser's Copy give an HTML clip (now any
text clip is read, its text part); the code floor moves only when the page turns into "send"; the sign-in goes on when the
window's screen is gone; the follow count after a tap during the first read; the address only from a shown element whose
own text says "sent to" (never hidden text, scripts or "consent to"); no binding on Android 15+.

Third pass (those fixes): no HIGH or MEDIUM; 1 LOW, fixed: a Follow tap still on its way is counted once. The page reader
was compiled from the Java source and checked as valid JavaScript (`node --check`).

## 6. Decisions left to the owner

- Codes from e-mail notifications stay a per-phone opt-in (Android's own switch) and are offered on Android 8-14 only.
  Reading the e-mail itself (Gmail API) would need a Google OAuth client and Google's review: not built.
- Creator levels are worked out by the app from public data (rules shown with the badge); GitHub itself has no verified
  mark for people. Other rules (for example a manual "trusted" list kept in the repository) are possible on request.
- The country comes only from the creator's own GitHub Location; nothing is guessed.
- Git LFS: with v2.1.4 the `binaries` branch holds about 4.7 GB of the free 10 GiB storage; every phone on v2.1.3
  downloads the 143 MB APK once (10 GiB a month of bandwidth on GitHub Free, about 70 downloads).
