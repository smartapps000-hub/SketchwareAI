
## 4. Changed from the ask, or not built, and why

- **Sign-in inside the app's WebView** is built as asked. OAuth's guidance for apps (RFC 8252) prefers the system browser,
  because an app can in principle read what is typed into its own WebView. The window keeps that risk small: only
  github.com pages open, there is no bridge from the page into the app, and the one script the app runs touches only
  the code boxes on `/login/device` (never a password field) and never presses Continue or Authorize. GitHub's
  authorize page still names the app ("SketchwareAI") and lists the access. Inside a WebView, GitHub's "Continue with
  Google" and passkeys aren't available (Google refuses embedded sign-in; passkeys need browser support): password +
  2FA code (or GitHub Mobile) work.
- **AuthGuard in "Built-in Library unpacking (BuiltInCache)"**: the repair BuiltInCache runs at app start is not gated:
  stopping it would leave a damaged library cache for the next build. Every build and export that uses the libraries is
  gated (Run, each export button), and so is the Library Manager.
- **Owner-only bypass**: still not built (a name check in public code is a backdoor anyone can use; v1.9.9 section 4).
- **`require_login`** stays `false` in `config/app-control.json`; the gate asks only when the file was read online in
  that run and sign-in can work on the phone (no WebView, Keystore failure, Device Flow off lift it for the run).
- **Auto-backup of new projects** only when signed in (there is no account to back up to otherwise); a project made
  offline waits and goes up from the main screen later (at most every 10 minutes) or right after a sign-in.
- **Known limit**: two local projects with the same name and package share one backup path in `SketchwareAI-Projects`
  (as since v1.9.8).

## 5. Device checks (the owner)

1. Install v2.0.0 over v1.9.9. Open the drawer: the GitHub card is under the Sketchware AI card.
2. Tap **Sign in with GitHub**: GitHub's page opens inside the app. Sign in, check the code is in the boxes, tap
   Continue and Authorize: the window must close by itself and the drawer card show your picture, name, @username and
   e-mail. If the code isn't filled in: type the code shown at the top (tap it to copy) and tell me.
3. Create a new project: a toast "<name> backed up to GitHub" a few seconds later. Then a project's **Back up > To
   GitHub**.
4. **Restore projects > Import from GitHub**: restore one of your backups; then paste the link of a public repository
   that has a .swb.
5. Projects #644, #623, #606: Run each once.

If something fails: a screenshot of the window's top line (it says what happened), or the compile log (Copy).
