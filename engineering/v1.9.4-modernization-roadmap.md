# v1.9.4 modernization roadmap (2 Nov 2026)

Owner's directive "LEGACY SKETCHWARE-PRO (2023) TO MODERN ANDROID 17 / 2026". Rule from the directive: 6.4.0-rc05's
block and palette names stay (projects and the precompiled editors depend on them); only the code the generator writes
changes. Existing projects keep working: a change is either the same behaviour in newer code, or a new opt-in block /
component. Facts: `engineering/v1.9.4-live-component-audit.md`.

| # | Legacy (6.4.0-rc05) | Modern replacement written by Sketchware AI | Status |
|---|---|---|---|
| 1 | Activities draw under the system bars on Android 15+ (target 35+) | `SystemBarsCode`: inset listener on the content (`WindowInsets.Type.systemBars() | displayCutout()`, IME), scrims in the theme's bar colours; edge-to-edge switch | **done** (framework API: no AndroidX needed, compiles for min SDK 19) |
| 2a | File blocks: `READ/WRITE_EXTERNAL_STORAGE` for every target | `READ_EXTERNAL_STORAGE` `maxSdkVersion 32`, `WRITE_EXTERNAL_STORAGE` `maxSdkVersion 29`; on 33+ the media permissions only when a block reads media (`READ_MEDIA_IMAGES` / `_VIDEO` / `_AUDIO`), and on 34+ `READ_MEDIA_VISUAL_USER_SELECTED` for partial photo access; FileUtil writes to app-specific folders or MediaStore on 29+ | **v1.9.4: the permission blocks' Storage/Media group** (request, state, events; manifest with those maxSdkVersion values, listed in the build log). The File blocks' own declarations and onCreate request are unchanged: with maxSdkVersion their onCreate check would ask again at every start on Android 11-12 (review finding); moving them needs the onCreate request code changed too |
| 2b | Notification component without `POST_NOTIFICATIONS` | the permission declared and requested at run time for target 33+ when the component is used | **v1.9.4: the Notifications permission block** (declares and requests POST_NOTIFICATIONS on 33+). The Notification component itself still asks for nothing |
| 2c | Sharing / installing files | `androidx.core.content.FileProvider` in the manifest (`Ix.writeFileProvider`), `content://` URIs; the IDE installs built apps through FileProvider | **done** |
| 3a | MediaPlayer / VideoView components | a new Media3 (ExoPlayer) component and blocks (HLS / DASH / MP4, background playback, PiP trigger, audio focus); the old components stay for existing projects | planned; Media3 as a built-in library needs its minCompileSdk and Kotlin metadata checked against the bundled android-37 jar and the embedded kotlinc 1.7.10 (CLAUDE.md 5a) |
| 3b | SMS receiver for OTP | no such block exists in 6.4.0-rc05 or here; new opt-in components for Credential Manager (passkeys / passwords) and SMS User Consent | planned; needs Play services auth-api-phone and the project's own Google Cloud setup for passkeys |
| 4 | Firebase / Maps / AdMob / OneSignal held at 2021-2022, Dynamic Links (service shut down) | one migration to current versions (min SDK 23 for projects that use them), Dynamic Links component marked as no longer working | planned |
| 5 | Web blocks (download, file chooser, user agent) | `SketchWeb` helper + blocks (owner's priority 1, `v1.9.3-ecosystem-audit.md`) | **done in v1.9.4** (downloads, desktop mode, clear data, file upload, download events; no SSL-error bypass) |
| 6 | 16 KB pages and signing | Run builds zip-aligned `-P 16` and signed v1 + v2 + v3; exports v1 + v2 + v3; AABs 16 KB-aligned; IDE ELF files 16 KB | **done** |

Order: 5 (web blocks, decided) → 2b → 2a → 3a → 4 → 3b. Each item ships with a fixture project that uses it, built in the
ART harness, exported, and its export built with Gradle.
