## 3. Review (separate agent, before the final build; it stopped once at the usage limit and was resumed)

No blockers. Applied: (1) permission names widened to whole groups (SEND_SMS also asked RECEIVE / READ_SMS, COARSE asked
FINE, ...) → only names whose meaning moved between versions are aliased; (2) DayNight with replaced activity files /
layouts (literal black text at night) → dark only where M3Widgets is on; (3) a manifest-editor theme that isn't AppTheme*
→ Material widgets off; (4) `void onBackPressed()` in an add-source block → no default back code (duplicate method);
(5) RemoteViews / progress drawables anywhere in code → ProgressBars stay framework; (6) to the owner: mixed content and
`window.open` (release notes); (7) download entry stored under the receiver's lock; (8) `filename*=` quoted /
ISO-8859-1, octet-stream filter; (9) picker: custom names need a dot, Settings-only / system permissions left out, list
at most half the screen; (10) shorter drawer titles. Kept: `material3()` for every AppCompat project and DayNight by
default (the owner's directive), old projects change look at their next build (README, release notes).
