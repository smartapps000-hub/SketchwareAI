# System audit, 11 Nov 2026 (v1.9.7, Android 17 / API 37)

Audited: source at `main` 29929c8 and the shipped APK `v1.9.7-34fabe7-minApi26` (sha256 `067a92b3…ab90c488`).
Request: the owner's 10 Nov 2026 "exhaustive system architectural, UI/UX & GitHub cloud IDE audit" (two directives; the
second is a subset of the first). This is an audit only: no code was changed.

**How to read this.** Every number below was measured on the source tree, the git history or the APK with the command
named next to it. Nothing here was run on a phone. A large part of the requested scope (GitHub sign-in, cloud sync,
community store, GitHub Models, MCP, security sheet, PWA shortcut, payments, deep links) **does not exist in the code**:
it is listed in section 3 as "not built" and is not scored as if it existed.

## 1. Executive scorecard

| Area | Score | Why |
|---|---|---|
| Platform compliance (API 37, 16 KB) | **7 / 10** | compileSdk 37 and all four native libraries 16 KB aligned. The IDE itself targets 35, not 37; projects it builds default to target 37. Legacy storage in the IDE and in generated File blocks. |
| Material 3 and glass UI | **5 / 10** | Apps the IDE *generates* are Material 3. The IDE's own screens are the 6.4.0-rc05 layouts on a MaterialComponents Bridge theme with the Obsidian layer on 75 of 528 layouts; no Material 3 colour roles, no real blur. Three text contrasts are below WCAG AA. |
| GitHub cloud and PKCE security | **1 / 10 built** | None of it is implemented (0 files). The one applicable check passes: no client secret or token anywhere in the tree, the git history or the APK. |
| Compiler and DEX stability | **8 / 10** | 14 of 14 fixture builds pass on the release APK, the library cache race is fixed, R8 is off so nothing is shrunk. Memory use on a phone was not measured. |
| Web and download engine | **6 / 10** | Names, HEAD-only check, two-layer ad block and Back are built and pass 77 checks off-device. The security sheet and the PWA shortcut are not built. Nothing was run on a real page. |
| Security (second directive) | **6 / 10** | No secrets shipped. The APK is signed with the public test key, cleartext traffic is allowed, backup is on, and upstream's Firebase identifiers still sit in the resources. |

### 2.6 Compiler and cache

- R8 keep rules for the embedded Kotlin compiler: not applicable today, because the IDE is built without shrinking.
  They become necessary only if R8 is ever switched on (rejected in v1.8.9).
- `compiledLibs` cache: aapt2 writes `<library>.tmp-<thread>-<nanoTime>.zip`, then renames it over the cached name
  (`ResourceCompiler.java:529, 546`). It is a write-then-swap, not a lock. Two lanes built 908 and 932 at the same
  time on one cache folder with no failure (v1.9.7 verification).
- 14 of 14 fixture builds pass on the release APK. `android:largeHeap="true"` (manifest line 34). Heap use of D8 and
  the DEX merger on a phone was not measured. DEX generation is Java code and does not depend on the kernel's page
  size; the only native tool is aapt2 (aligned, section 2.2). No build was run on a 16 KB device.

## 5. Remediation roadmap

Ordered by what unblocks the most. Items marked **owner** need a decision or an action only he can take.

1. **Private release key (owner).** Create a keystore that never enters the repository, sign releases with it, and
   register the package and key for Android developer verification before it applies in his country. Installing over
   a test-key build is not possible: users uninstall once, so project data in `/.sketchware` must be confirmed to
   survive (it lives outside the app's data). Nothing about sign-in can start before this.
2. **Contrast (three small patches).**
   - Call-to-action: either set `Ob.Text.Button.Cta` `android:textColor` to `#FF0B0B0D` (5.24 to 7.02:1), or keep
     white and darken the gradient to `#B93C0A` / `#C2410C` (5.65 / 5.18:1). **Owner** picks; the gradient is his
     approved token.
   - Guide blocks: keep white and draw the guide's teal as `#00796B` (5.32:1) and brown as `#795548` (6.55:1), or keep
     the authentic colours and accept 3.3 to 3.7:1. **Owner** picks.
   - Hints: replace `#FF71717A` with `#FF8E8E93` (6.03:1) in the two layouts. For AAA on cards, use `#B4B4BD`
     (8.07:1) for secondary text there.
3. **v1.9.8 as agreed:** multi-tab WebView blocks, the security settings sheet, the home-screen shortcut. Two limits to
   state in the UI: the secure-DNS row can only open Android's Private DNS setting, and the shortcut is a pinned
   shortcut to a full-screen WebView activity, not a WebAPK.
4. **Storage blocks for generated apps (issue 3).** Add a photo-picker block (no permission) and a "save to Downloads /
   Pictures" block through MediaStore, keep the old File blocks for app-private paths, and make the build note say
   when a project uses a shared path that Android 11+ will refuse. This is the PhotoPicker / FullMediaAccess split
   already planned on 3 Nov.
5. **IDE to target 36, then 37 (issue 2).** (a) Replace `onBackPressed()` with an `OnBackPressedCallback` in the 32
   files; the precompiled activities need a small source subclass each or a bytecode-faithful source replacement.
   (b) Remove the edge-to-edge opt-out and add inset padding in `ObsidianWindow` for the toolbar and the bottom bars.
   (c) Render every screen group in layoutlib, then a phone pass. This is its own release.
6. **Hardening without behaviour change:** `usesCleartextTraffic="false"` plus a network-security config if any
   feature needs plain http; `allowBackup="false"`; blank the values of the six upstream Firebase strings and keep
   their names (the IDs are pinned).
7. **GitHub sign-in, when the owner re-opens it.** First a ten-minute test with a throw-away OAuth app: does the token
   exchange succeed with a PKCE verifier and no client secret? If yes, use PKCE in a Custom Tab; if no, use the device
   flow. Either way no secret is in the app. Store the token encrypted with a key generated in the Android Keystore
   (AES-GCM), in private preferences, with backup off.
8. **Sync and store, after sign-in.** Start with the REST contents and git-data endpoints for one project per private
   repository; add a local history only when conflicts make it necessary. A store on Discussions needs a signed-in
   user for every read (GraphQL); Releases can be read without a token at a low hourly limit.
9. **AI assistance.** GitHub Models no longer exists, so that part of the design needs a different provider and a
   key the user supplies. The standing rule "no cloud model in the build" still holds: an assistant may suggest, the
   build must not depend on it. **Owner** decides whether this is wanted at all.
10. **Payments and deep links.** A UPI intent or a payment link can be opened from the app, but the app cannot confirm
    a payment by itself; that needs a server. Decide the model before any code. A custom scheme link is a manifest
    entry plus one activity once the store exists.
11. **AGP 10 readiness (issue 10).** Either keep AGP 9.x, or replace the pinned-ID mechanism: this is tied to the
    precompiled jars and is a large change.
12. **Blur, if wanted (issue 8).** `RenderEffect` on API 31+ behind the glass panels with the current gradient as the
    fallback below; measure scroll performance on the phone first. **Owner** decides.
