# Android runtime harness (ART API 31, no framework)

Runs Sketchware AI's own **Run build** on a real Android runtime inside a Linux workspace, with the classes of a
built IDE APK: project data written and read by the IDE's own classes (lC/hC/iC/eC/kC/jC), sources generated by
yq/Jx/Ox/Lx, resources compiled and linked by the APK's own `libaapt2.so`, Java compiled by its ECJ, dexed by its
D8, packaged and signed by its own code. Only the Activity screens are not run.

1. `setup-art.sh <work dir>` (once per workspace; downloads the Android 12 x86_64 system image).
2. `mk.sh` builds `out/stubs.zip` (the framework stand-ins in `stubs/`), `out/harness.zip` (`src/h`) and
   `out/android-dex.zip` (the IDE's bundled android.jar, dexed; its other classes throw `Stub!`).
3. Inputs for two fixtures (once per workspace): `make-test-fonts.py out/fonts` (909; OFL fonts from npm @fontsource,
   modified copies for tests only, never shipped) and `make-native-fixture.sh out/native-fixture` (910; NDK clang).
4. `suite.sh <IDE apk> <tag> libs:901 held:902 plain:903 kotlin:904 autofix:905 typo:906 min19:907 m3:908
   telugu:909 jni:910 desugar:911 m3code:912 m3dark:913` (a spec name ends up in a package name: never a Java keyword)
   or one fixture: `run.sh <IDE apk> <root> create libs 901` then `run.sh <IDE apk> <root> build 901 [resume step]`.
   `run.sh <IDE apk> <root> aab <id> [resume step]` runs the export screen's Export AAB (export build, DEX merge,
   AppBundleCompiler, bundletool (1.18.3 since v1.8.5), BundleSigner with the test key since v1.8.5) into
   `<root>/signed_aab/`; it deletes `mysc/<id>`, so copy the debug APK first. `run.sh <IDE apk> <root> export <id>` runs
   "Export to Android Studio" (the Gradle project lands in `mysc/<id>`).
5. `art.sh out/stubs.zip:out/harness.zip:out/android-dex.zip h.LoadAll <built app apk> <app package>` loads and
   links every class of a built app (ART verifier, stubs of the bundled android.jar, API 34 since v1.8.4).
   `art.sh out/stubs.zip:out/harness.zip:out/android-dex.zip:<904 apk> h.CallKt` runs fixture 904's Kotlin code,
   `...:<911 apk> h.CallDesugar` fixture 911's desugared Java 8+ API calls.
   `ART_OPTS="-Xmx1536m -Dh.root=<root>" art.sh out/stubs.zip:out/harness.zip:<IDE apk>:out/android-dex.zip h.L8Race
   <min sdk> <keep rules file> <android.jar> race|one` runs CoreLibDesugaring.libraryDex (L8) from two threads at once
   (or once, e.g. with a small -Xmx); `<root>/cache/libs/desugar/` needs the three files of assets/libs/desugar.zip.

Fixtures (`src/h/Fixtures.java`): see `engineering/test-fixtures.json`. Widget defaults come from the palette
icons (`src/h/IconDefaults.java`, generated from `dev/aldi/sayuti/editor/view/palette/Icon*.getBean`).

Facts that cost time: ART aborts at start with `-Xmx` above ~1.5 GB; `/linkerconfig/com.android.art/ld.config.txt`
must exist and every namespace must be `visible = true`; `/system/etc/public.libraries.txt` must not be empty
(signing loads a native library); `SystemLogPrinter.start()` (Dp constructor) sends System.out/err to
`/.sketchware/debug.txt`, so the harness prints to FileDescriptor.out; aapt2 runs fine from ART here; kotlinc leaves
non-daemon threads, so `Main` ends with `System.exit`; `.sketchware/bak/<id>` is the IDE's working copy of a project and
must be deleted with `data/<id>` before an id is reused (suite.sh does), or every view is added twice.

v1.8.6: fixture 913 `m3dark` (a new project with dynamic colour on: DayNight + values-night colour roles, buttons with
their own background colour, a button whose background the code reads, the long-hint 12sp field); 912 `m3code` stores no
dark setting (a v1.8.5 Material 3 project, stays light). `run.sh` extracts the APK's aapt2 into `out/native-run/<pid>`:
with one shared folder, a second lane could run the file while the first was rewriting it (`error=13`).
